    Inspect sensor estimates and limits

    The MPU6050 IMU, BMP280 barometer and GNSS models use discrete samples, seeded noise and fixed bias. They do not use measured hardware specifications. Raw observations are separate from estimated attitude, height, velocity and position. GNSS provides noisy pad-relative X/Y position and velocity in the known target frame, not direct access to true state.

    Read calibration and drift assumptions

    Static preflight accelerometer alignment initializes roll and pitch. The measured gyro mean estimates rate bias. Both require a motionless calibration interval. In flight, calibrated gyro propagation does not treat powered thrust acceleration as gravity.

    Heading starts at zero without an absolute reference. XY GNSS does not directly measure yaw. Barometric height starts from its observed sample. GNSS corrects IMU-predicted XY by default. Without GNSS, position drifts from the known scenario position and zero initial lateral velocity. Residual bias, heading error and sensing limits can still cause failures.

    Inspect the control loops

    Feedback uses the selected sensor estimates or ideal truth comparison. Sensor mode uses gyro-propagated attitude, GNSS-aided IMU XY, barometric clearance and vertical speed, and preflight-bias-calibrated gyro rates. Disabling GNSS leaves drifting IMU-only XY. No hidden true XY enters sensor feedback. Mass, inertia, fuel and actuator position remain known model parameters.

    Outer guidance requests pitch and roll. Both inner loops use the same PID gains. Two-axis thrust vectoring produces attitude torque only while thrust is available. Vertical guidance commands finite throttle. Rocket thrust pivots below the centre of mass. Monocopter thrust pivots above it, reversing the torque sign. Neither mode has a yaw actuator or absolute heading aid.

    Platform electronics
    MCU
    STM32F411CCU · real-time flight controller
    IMU
    MPU6050 · 3-axis accelerometer + 3-axis gyroscope
    Barometer
    BMP280 · pressure and temperature; pressure-derived altitude
    Sensor link
    I²C for MPU6050 and BMP280; sensor calibration and timestamping required
    TVC interface
    Proposed PWM commands to two gimbal servos; actuator limits and response must be measured
    Power
    3.3 V MCU/sensor logic; separate regulated actuator supply, shared signal ground
    Companion
    Proposed Raspberry Pi for vision and bounded mission assistance; STM32 retains control authority
    Telemetry / logs
    Planned UART telemetry and independent flight logging; watchdog and power monitoring
    Position / range
    Simulated GNSS aiding; physical GNSS module not selected. Downward radar/lidar remains proposed for low-altitude range.

    Hardware reference only. This simulator is not connected to an MCU or sensors; radio, storage, servo models and pin assignments are not yet specified.
