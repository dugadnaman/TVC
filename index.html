    07 Sensor estimates vs true state

    Controller feedback: SENSORS · simulated GNSS-aided XY and preflight-calibrated gyro rates.

    Illustrative MPU6050 IMU, BMP280 barometer and simulated GNSS: discrete sampling, seeded noise and fixed bias; not measured hardware specifications. Raw observations are separate from estimated attitude, height, velocity and position. GNSS samples are noisy pad-relative X/Y position and velocity in the known target frame, not direct controller access to true state.

    Static preflight accelerometer alignment initializes roll/pitch; the measured gyro mean estimates rate bias. Both assume a motionless calibration interval. In flight, calibrated gyro propagation does not treat powered thrust acceleration as gravity. Heading starts at zero without an absolute heading reference; XY GNSS does not directly measure yaw. Barometric height starts from its observed sample. Simulated GNSS corrects IMU-predicted XY by default; disabling it leaves drifting dead reckoning from the known scenario position and zero lateral velocity. Residual bias, heading error and illustrative sensing limits can still cause failures.

    08 Control loops · selected feedback

    Feedback paths use the selected sensor estimates or ideal-truth comparison baseline. Sensor mode uses gyro-propagated attitude, simulated GNSS-aided IMU XY (or drifting IMU-only XY when disabled), barometric clearance and vertical speed, and preflight-bias-calibrated gyro rates; no hidden true XY enters sensor feedback. Mass, inertia, fuel and actuator position remain known model parameters. Outer guidance requests pitch and roll; the same gains tune both inner loops. Two-axis thrust vectoring provides attitude torque only while thrust is available. Vertical guidance commands finite throttle. Rocket thrust pivots below the centre of mass; the monocopter propeller pivots above it, reversing the torque sign. Neither mode has a yaw actuator or absolute heading aid.

    Platform electronics

    MCU
    STM32F411CCU · real-time flight controller
    IMU
    MPU6050 · 3-axis accelerometer + 3-axis gyroscope
    Barometer
    BMP280 · pressure and temperature; pressure-derived altitude
    Sensor link
    I²C for MPU6050 and BMP280; sensor calibration and timestamping required
    TVC interface
    Proposed PWM commands to two gimbal servos; actuator limits and response must be measured
    Power
    3.3 V MCU/sensor logic; separate regulated actuator supply, shared signal ground
    Companion
    Proposed Raspberry Pi for vision and bounded mission assistance; STM32 retains control authority
    Telemetry / logs
    Planned UART telemetry and independent flight logging; watchdog and power monitoring
    Position / range
    Simulated GNSS aiding; physical GNSS module not selected. Downward radar/lidar remains proposed for low-altitude range.

    Hardware reference only. This simulator is not connected to an MCU or sensors; radio, storage, servo models and pin assignments are not yet specified.
